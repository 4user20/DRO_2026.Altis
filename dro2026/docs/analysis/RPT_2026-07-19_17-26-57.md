# RPT-анализ: Arma3_x64_2026-07-19_17-26-57

Дата разбора: 2026-07-19  
Версия движка: Arma 3 2.20.153940  
Режим: Client / hosted single-player  
Связанные dump-файлы: `FROZEN0.mdmp`, `FROZEN11.mdmp`, `.bidmp`

## Краткий вердикт

В логе подтверждены три собственных регрессии DRO 2026 и один опасный сценарий взаимодействия с модпаком:

1. faction scan терял локальную `_thisFac`, потому что `BIS_fnc_GetCfgData` мог вернуть `nil`;
2. диагностическое выражение использовало массив как predicate для `count`;
3. `clientInit` завершался через четыре минуты ожидания лобби и не устанавливал панель поддержки;
4. legacy support generator автоматически выбрал тяжёлую Pook-систему, после чего позднее в сессии появился длительный внешний `"[DEBUG] FIRED"` spam.

Точная функция падения по minidump не установлена: dump-файлы являются watchdog MiniDump без доступных PDB/символов Bohemia и сторонних аддонов.

## Подтверждённые ошибки миссии

### 1. `_thisFac` / `_isPlayerFaction`

Симптомы:

```text
Undefined variable in expression: _thisFac
Undefined variable in expression: _isPlayerFaction
```

Причина: faction classname читался через `BIS_fnc_GetCfgData`. При отсутствующем/пустом свойстве функция могла вернуть `nil`; присваивание `nil` удаляло локальную SQF-переменную.

Исправление:

- `getText (_cfgVehName >> "faction")`;
- `private` для per-class флагов и faction indexes;
- безопасные индексы `-1`;
- регрессионный semantic check.

### 2. Массив вместо Boolean

Симптом:

```text
Error Тип Массив, ожидался Булево
```

Причина:

```sqf
({_x} count _pInfEditorSubcats)
```

Code block возвращал `_x` — массив, а `count condition` ожидает Boolean.

Исправление: обычный `count _pInfEditorSubcats` / `count _eInfEditorSubcats`.

### 3. Панель поддержки не устанавливалась

Таймлайн:

```text
17:36:03 [DRO2026] clientInit: playersReady timeout
~17:42    playersReady / старт операции
```

Пользователь находился в конфигурационном лобби дольше четырёх минут. `clientInit` завершился через `exitWith`, поэтому communication item и action поддержки никогда не добавлялись.

Исправление:

- ожидание `playersReady` не имеет искусственного lobby deadline;
- единственная причина выхода — завершение миссии;
- каталог после старта ожидается отдельно не более 90 секунд;
- панель доступна и через communication menu, и через защищённый `addAction`.

### 4. Три одинаковые задачи наблюдения

RPT:

```text
DRO: taskIDs = ["D26_ISR_...", "D26_ISR_...", "D26_ISR_..."]
```

Причина: в фазе `RECON` ISR opportunity получал большой бонус, а штраф повтора был недостаточен. Тип и capability-node не резервировались жёстко.

Исправление:

- уникальность objective type и node;
- ISR только по конкретному неизвестному capability-node;
- физический ISR relay с антенной, генератором, машиной управления и операторской группой;
- наблюдение/уничтожение relay раскрывает конкретный склад, артиллерию, ПВО, РЭБ, FPV/HQ или дальний drone-site;
- при отказе objective adapter selector пробует до четырёх других типов.

## Поддержка

Legacy `addSupports.sqf` выбирал случайный конкретный classname и физически создавал его до запроса игрока. В этом RPT был выбран тяжёлый Pook launcher.

Новая схема:

```text
selected lobby factions
  -> server refreshFactionAssets
  -> serialized support catalog
  -> category selection
  -> exact displayName/classname selection
  -> quantity
  -> map point
  -> server validation
  -> physical support creation
```

Поддерживаются конкретные:

- FPV auto/manual;
- ISR airframes;
- FP-1 / FP-2 / BM-35 / Bulava / FP-5 launcher profiles;
- physical long-range airframes, включая Shahed/Geran;
- artillery systems;
- CAS aircraft/helicopters.

Launcher profile появляется только при разрешаемом штатном `CfgAmmo` либо зарегистрированном ammo fallback.

## Вражеский ISR → strike chain

Вражеский ISR теперь:

- не использует server-side global `player`;
- предпочитает `RUS_VKS_forpostru` для EAST, если класс доступен;
- самолётные БПЛА стартуют из глубокого тыла;
- последовательно обследуют HQ, ПВО, артиллерию, logistics, FPV/drone sites и физические support assets;
- создают contacts с устойчивым `subjectId`;
- tactical physical contacts разрешают FPV intent;
- confirmed strategic contacts разрешают long-range intent;
- EAST предпочитает Shahed/Geran против HQ/AA/logistics и BM-35 против artillery/drone nodes;
- enemy long-range salvo ограничен тремя аппаратами.

## Freeze / crash timeline

Поздняя часть сессии:

```text
17:58:40–17:59:46  повторяющийся внешний "[DEBUG] FIRED"
18:00:13+          No alive in 10000 ms
18:01:39           exception 80000101 / завершение процесса
```

Строка `"[DEBUG] FIRED"` отсутствует:

- в репозитории DRO 2026;
- строковым поиском в предоставленном архиве `3002626283`.

Следовательно, лог пишет другой Workshop-аддон. Миссия могла спровоцировать его большим количеством событий Fired, но не является источником debug handler.

Меры снижения риска в миссии:

- legacy artillery/CAS/UAV больше не создаются случайно при старте;
- известный нестабильный тяжёлый Pook launcher скрыт и отклоняется сервером;
- общий heavy-fire lock для артиллерии и CAS;
- не более одной тяжёлой support mission одновременно;
- enemy long-range salvo не более трёх;
- увеличены интервалы enemy FPV/ISR/long-range;
- player physical drone budget остаётся 10, но запуски staggered.

## Ошибки сторонних аддонов, не исправляемые миссией

В RPT также присутствуют:

- `camPos2` undefined в звуковых конфигах БПЛА;
- `speedX/speedY/speedZ` в particle-конфигах;
- отсутствующие ARI_AO nuclear scripts;
- ошибки selection/model/config у отдельных RUS/VDV машин;
- TFAR/MMM_R148 config warnings;
- отсутствующие texture/string assets;
- PiR fire/vehicle selection errors.

Эти ошибки нужно исправлять обновлением/патчем соответствующего addon PBO либо исключением конфликтного аддона из preset. Mission-side код может только не выбирать подтверждённо проблемные классы автоматически.

## Следующий runtime-тест

1. Обновить миссию из ветки/PR.
2. Запустить с `-showScriptErrors`.
3. Провести в лобби более пяти минут и убедиться, что панель появляется после старта.
4. Проверить категории и конкретные classnames.
5. Запросить ISR, FPV manual/auto, дальний залп 1/3/10, артиллерию и CAS.
6. Убедиться, что три стартовые задачи различны.
7. Найти физический ISR relay и раскрыть связанный узел.
8. Продолжить 30–45 минут и проверить отсутствие непрерывного Fired spam.
9. Передать свежий RPT; старый RPT нельзя использовать как подтверждение исправленного состояния.
